## 7. Факты, которые стоили часов (сохраните их)

* Номера героев: герои Olden Era получают номера WoG 0..155 на всю игру (свой id OE, если он свободен); номера без
  героя — герои пула H3 в `WoGGameState.PoolHeroes` (имена из hotraits.txt установки).
* Автосохранение Olden Era делается **до** начала её дня, и его загрузка начинает день; сохранение посреди дня — нет;
  `WoGGameState.DayStarted` делает так, что день проходит один раз для состояния WoG.
* Действующая таблица опыта — `dyx.chmm` в логике героя (50 уровней `exp_standard`), а не файл из Core.zip.
* Таблица заклинаний H3: строки sptraits.txt i+5 / i+8 / i+11; цель/анимация/флаги из `h3era.exe` по адресу 0x6854A0.
* Era местами снимает проверки параметров WoG (TR:T принимает любое число параметров, недостающие пропускаются);
  прежде чем считать число параметров ошибкой, посмотрите список хуков `Erm.pas` (около строки 9380).
* Значения WoG Options: собственный ZSETUP01.TXT WoG Scripts (231 пункт) поверх WoG (19) через VFS Era, плюс
  `.ers`-файлы модов; группы-переключатели и инвертированные опции 1..4 — по `wogsetup.cpp` `Prepare2Close`.
* События боя Olden Era (`eor.clgz.cksd`): начало раунда `ckso`, начало хода `cksj`, ход `cktd`, заклинание/атака
  `ckts`/`cktt`, ожидание `cksw`, пропуск (= защита) `cksv`, магия героя `cktn`/`cktm`, урон `cksq`.
* В прогоне корпуса ERA моды идут от высшего приоритета; тогда данные H3 берутся из нужного мода (ZSETUP01 WoG
  Scripts поверх WoG).

### 37. НИКАКОЙ ЛОЖНОЙ ГОТОВНОСТИ

Функция НЕ готова только потому, что:

* код собирается
* тест проходит
* команда ERM не бросает исключение
* значение есть в состоянии WoG

Функция готова, когда работает её задуманная игровая семантика.

Пример: HE:S не готов только потому, что работает `hero.skills.Add(...)`. Он готов, когда:

* меняется состояние навыков героя
* применяются бонусы
* интерфейс это показывает
* механика повышения уровня/поднавыков ведёт себя правильно
* скрипты видят изменённое состояние
* сохранение/загрузка его сохраняет

Применять эту планку везде.
