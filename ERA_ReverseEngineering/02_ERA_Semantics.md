# Семантика ERM в ERA (отличия от WoG 3.58)

Источник: `Erm.pas` (`Hook_ZvsGetNum`, `GetErmParamValue`, `SetErmParamValue`, `Hook_ZvsGetFlags`,
`Hook_ZvsCheckFlags`, `ProcessErm`, `InterpolateErmStr`, `New_VR_Receiver`, `Hook_FU_P`, `Hook_FU_EXT`, `DO_P`),
`AdvErm.pas` (`GetServiceParams`, `SN_*`), `Trans.pas`, `Extern.pas`. Порт: `src/WoG.Erm/Syntax/ErmParserEra.cs`,
`src/WoG.Erm/Runtime/EraValues.cs`, `EraProcess.cs`, `src/WoG.Erm/Receivers/EraReceivers.cs`, `EraApi.cs`.
Тесты: `EraParserTests`, `EraRuntimeTests`, `EraCorpusTests`.

## 1. Параметры

Порядок разбора одного параметра:

1. Пропуск пробелов (`#1..#32`).
2. Один префикс: `?` (получить), `d`-модификатор, сравнение (`=`, `<>`, `>`, `<`, `>=`, `<=`, `=>`, `=<`).
   Модификаторы ERA: `d` / `d+` (прибавить), `d-`, `d*`, `d:` (деление), `d%`, `d|` (ИЛИ), `d~` (И-НЕ),
   `d<<`, `d>>`; в параметрах `SN` ещё `d&` (склейка строк).
3. Основа: `v y x z e w` — переменная с индексом; `c` — прибавить текущий день (только для чисел).
4. Значение/индекс: `^строка^`, `i^имя^`, `s^имя^`, быстрая переменная `f`…`t`, `$макрос$`, число, или буква
   переменной + число (`vy5` = v[y5]).
5. Пропуск пробелов.

Типы значений: целые (`число`, `f..t`, `v`, `w`, `x`, `y`, `i^^`), дробные (`e`), строки (`z`, `s^^`, `^…^`),
логические (флаги, только в условиях и `%F`).

Отличия от WoG:
* строка `^…^` — **обычный параметр** (в WoG это «текст команды»); `IF:Q1^текст^` = два параметра;
* в выражениях можно ставить пробелы: `!!VRy1:Sy2 :5000 +1;`;
* параметры, которых нет в команде, **игнорируются** при установке (WoG выдаёт ошибку);
* `?` к `e`-переменной в целочисленной команде пишет **биты целого** в дробную переменную (так в ERA);
* у `FU`/`DO` может быть ноль параметров (`!!FU(F):P;`).

## 2. Условия `&` / `|`

* Элемент — `значение` или `значение<сравнение>значение`.
* Одиночное **число** — флаг: `&500` = флаг 500 установлен, `&-500` = сброшен.
* Одиночное **значение другого типа** приводится к логическому: число ≠ 0, строка не пустая (`&z1`).
* Числа сравниваются как целые или дробные (если одна сторона `e`), строки — **побайтно с учётом регистра**
  (в WoG — по словам и без регистра).
* Итог: (все `&` истинны и они есть) ИЛИ (хотя бы один `|` истинен). Ошибка в любом элементе отменяет
  команду.

## 3. Поток управления внутри секции

| Команда | Поведение |
|---------|-----------|
| `!!if&усл;` … `!!el&усл;` … `!!el;` … `!!en;` | `el` с условием — это «иначе если» |
| `!!re var/начало/конец/шаг/доб;` … `!!en;` | цикл: `var` = начало; пока `var <= конец` (при шаге ≥ 0) или `>=` (при шаге < 0); шаг по умолчанию 1; без `конец` — бесконечный цикл (выход через `br`); пятый параметр прибавляется к концу |
| `!!br;` / `!!br N;` | выход из N-го вложенного цикла |
| `!!co;` / `!!co N;` | следующий шаг N-го вложенного цикла |
| `!!SN:G<номер>;` | переход к команде с этим номером (номера даёт препроцессор из меток) |
| `!!FU:E;` | конец текущей секции (следующие секции события выполняются) |
| `!!SN:Q;` | конец обработки события: остальные секции не выполняются |

Глубина вложенности `if/re` — 16. Ошибка управления (`el` без `if`, `en` без пары, `br` вне цикла) прерывает
всё событие.

## 4. Локальные переменные и событие (`ProcessErm`)

При каждом событии (не при каждой секции, как в WoG):

* сохраняются и после события восстанавливаются: `y1..y100`, `e1..e100`, `x1..x16`, **быстрые переменные
  `f..t`**, `z-1..z-10`, флаги 996–1000, `v997..v1000`;
* обнуляются: `y1..y100`, `e1..e100`; `z-1..z-10` — кроме функций 1–29999 при `ErmLegacySupport`;
* `x1..x16` = аргументы вызова (`ArgXVars`), по окончании — результат (`RetXVars`);
* `y-1..y-100` при `ErmLegacySupport` сохраняются для не-функций и обнуляются перед каждой секцией классических
  триггеров (таймеры, объекты, …); без этой опции они глобальны;
* после всех секций вызывается функция `<ИмяСобытия>_Quit`, если она объявлена;
* флаг 999 — «ход человека на этом компьютере», флаг 1000 — «человек-посетитель/настоящая битва»,
  `v998..v1000` — координаты события.

`ErmLegacySupport` в поставке ERA Project включена (`default heroes3.ini`), в порте по умолчанию тоже
(`ErmRuntimeOptions.EraLegacySupport`).

Следствие: в ERA `y`-переменные живут **через все секции одного события**, а быстрые переменные `f..t`
**локальны** (изменения внутри триггера не видны снаружи). Скрипты WoG, рассчитывающие на поведение 3.58,
в ERA уже переписаны — поэтому эталон поведения именно ERA.

## 5. Функции

* `!!FU(F):P a/b/?c;` — `x1..xN` = значения; `?число` передаёт текущее значение и получает результат
  («по ссылке»); `?строка` получает строку, на которую функция указала в `xN` номером строки
  (например, `!!VRx1:Z^текст^`); локальная `z-` строка копируется во временную строку; `d-` меняет знак.
* `!!FU:A?n;` — сколько аргументов передано; `!!FU:A5/6;` — значения по умолчанию для непереданных.
* `!!FU:S#/?r;` — как был передан аргумент # (0 — `?`, 1 — значение, 2 — с `d`).
* `!!DO(F)/начало/конец/шаг:P…;` — событие повторяется целиком, счётчик — `x16`; остальные `x` между
  итерациями сохраняются.
* `!!FU:D` — сетевой вызов (в порте не поддержан: только одиночная игра).

## 6. Строки

* `z1..z1000` — глобальные, `z-1..z-10` — локальные, `z>1000` — строки из файлов `.ert`,
  `z ≥ 1 000 000 000` — временные строки (литералы команды, результаты функций). Временные строки команды
  живут до конца строки команды, строки триггера — до конца события.
* **Интерполяция** `%…` — один проход (в WoG — 5): `%y1`, `%Y1`, `%vy5`, `%i(имя)`, `%s(имя)`, `%F5`,
  `%e1` (3 знака после точки), `%Dd/%Dw/%Dm/%Da`, `%Gc`, `%T(ключ)` (перевод), `%Vf..%Vt`, `%%`, `%\:` (`;`),
  `%\"` (`^`). Содержимое `z1..z1000` при выводе **не интерполируется** (в WoG — да), строки ERT — да.
* `VR:U` — «содержит» (без регистра, по обрезанным строкам); в WoG — «оканчивается на».

## 7. `VR` (переписан ERA)

`S` с правилами типов (целое ← дробное: отбрасывание дробной части или округление вторым параметром:
0 — к ближайшему, <0 — вниз, >0 — вверх), `+ - * : %` (смешанные целые/дробные считаются в дробных;
`+` к строке — склейка), `& | X ~` (только целые), `B` (в 0/1), `C` (несколько переменных подряд, в т. ч.
`y-`), `F` (ограничить диапазоном, со значением по умолчанию), `H` (флаг «строка не пустая»), `M1..M6`
(подстрока, N-е слово, число → строка в системе счисления, длина, первая/последняя значимая позиция),
`R` (случайное: `R0/мин/макс`, `R0/сид`), `T` (случайное без сида), `V` (строка → число), `U`, `Z`
(создать временную строку триггера и записать её номер).

## 8. `SN` и именованные переменные

| Команда | Что делает | Порт |
|---------|-----------|------|
| `SN:W^имя^/значение` | именованная переменная (целое или строка) | да |
| `i^имя^`, `s^имя^` | то же прямо в параметрах | да |
| `SN:M` | динамические массивы: создать (`-1` — новый номер, хранение: −1 — до конца триггера, 0 — временный, 1 — сохраняемый), размер, элемент | да (адреса элементов — нет) |
| `SN:V` | несколько элементов массива сразу | да |
| `SN:K` | длина строки, символ по номеру | да (копирование памяти — нет) |
| `SN:X` | чтение/запись `x` текущего вызова | да |
| `SN:T^ключ^/?z#/имя/значение…` | перевод с подстановкой `@имя@` | да |
| `SN:C^ИМЯ^/?значение/?есть` | значение константы | да |
| `SN:G`, `SN:Q`, `SN:I`, `SN:D` | переход, выход, интерполяция строки, перерисовка | да (`D` — ничего не делает) |
| `SN:F^имя^/…` | вызов функции API Era (результат в `v1`) | часть функций (таблица ниже) |
| `SN:H` (подсказки), `SN:O`, `SN:P`, `SN:S`, `SN:R` | интерфейс, звук, ресурсы H3 | нет (нужен UI/ресурсы Olden Era) |
| `SN:E`, `SN:L`, `SN:A`, `SN:B` | вызов кода по адресу, DLL, память | невозможно |

Ошибка ERA, сохранённая в порте: в параметрах `SN` модификатор `d|` выполняет **И**, а не ИЛИ
(`ApplyIntParam`).

### Функции API Era, доступные через `SN:F` в порте

`ShowErmError`, `ExtendArrayLifetime`, `IsCommanderId` (монстры 174–191), `IsCampaign` (0), `Hash32` (CRC32),
`SplitMix32`, `Erm_Substr`, `Erm_StrTrim`, `Erm_StrReplace`, `Erm_StrPos`, `Erm_Interpolate`,
`Erm_CompareStrings`, `Erm_IntLog2`, `trStatic`, `PluginExists` (0), `PcxPngExists` (0), `Disable/Enable/Restore/
ResetErmTracking` (ничего не делают), `GetProcessGuid`; Win32: `GetKeyState` (0), `GetModuleHandleA` (0),
`GetFileAttributesA` (−1), `FindFirstFileA` (−1). Остальные (`GetButtonID`, работа с ini, `FormatQuantity`,
`GetGameState`, сортировки массивов по адресу, функции плагинов `dll:функция`) — UNSUPPORTED, выполнение
продолжается.

## 9. Что принципиально непереносимо

* `UN:C`, `SN:B/L/A`, `SN:E`, `SN:M …/?адрес`, `SN:K` с копированием памяти — работают с памятью и кодом
  процесса Heroes III. Скрипты, которые на них опираются, нужно переводить на ресиверы/адаптер по месту.
* Ресиверы плагинов (`SS`, `PA`, `QU`, `RD`) и функции плагинов (`SN:F^плагин:функция^`) — закрытые DLL;
  их можно реализовать заново только по описанию поведения.
