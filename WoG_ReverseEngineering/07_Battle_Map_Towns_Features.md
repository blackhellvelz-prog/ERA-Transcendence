# Бой, карта приключений, города и набор возможностей WoG

Источники: `T1/Monsters.cpp` (ресиверы и хуки боя), `T1/casdem.cpp` (города, снос), `T1/womo.cpp` (бродячие
монстры), `T1/erm.cpp` (ресиверы объектов, `EventERM`, `ERM2Object`), `wog features.html` (S4), скрипты 3.58f (S7).

## 1. Как устроен WoG — ключевой факт для порта

WoG 3.58 = **(а)** расширение движка на C++ (интерпретатор ERM, командиры, опыт стеков, новые таблицы
существ/артефактов, хуки боя и объектов, опции) **+ (б)** ~77 ERM-скриптов, реализующих большинство видимых
«фич WoG» (новые объекты вроде Старьёвщика или Пещеры приключений, Неделя монстров, Приспешники, Улучшенные
вторичные навыки, Правила карты, …).

Отсюда стратегия порта: (а) переписать нативно в WoG Core, а (б) выполнять **без изменений** через рантайм ERM.
Каждая фича из (б) заработает, как только отображены на Olden Era используемые ею ресиверы.
`03_ERM_Receivers.md` ранжирует ресиверы по реальному использованию; парсер порта уже разбирает все 78 файлов
скриптов 3.58f без ошибок.

## 2. Жизненный цикл боя (порядок триггеров — из `BACall`, `BACall2`, `BACall3`, `BFCall`, `MFCall`, справки)

```
BA0 (ПК атакующего) | BA50 (ПК защитника) → BA52
  └─ BF (подготовка поля: препятствия, ресивер BF)
      └─ размещение командира/доп. стеков (PlaceNPCAtBattleStart), применение опыта стеков (CrExpBon::Apply)
          └─ BR v997=-1 (до тактики) → [тактика] → BR v997=0
              └─ на каждое действие: BG0 → родное действие (внутри — хуки MF/MR в расчёте урона/сопротивления) → BG1
              └─ на каждый раунд: BR v997=n, CrExpBon::Apply2 (бонусы раунда), регенерация
BA1 | BA51 → BA53  (после боя: выживание командира CheckForAliveNPCAfterBattle; опыт стеков AddExpo)
```

Ресиверы боя:

| Ресивер | Селектор | Назначение |
|---------|----------|------------|
| `BA` | — | бой в целом: герои (`H`), владельцы (`O`), позиция (`P`), быстрый бой (`Q`), модификаторы |
| `BM` (`ERM_BRound`) | номер стека (0…41) | стек в бою; команды `T N L B E I A D H S F O R J U` (тип, число, атака `A`, защита `D`, скорость `S`, флаги `F`, позиция `O`, …; полное значение — страница справки `rebm_r`) |
| `BU` | — | общее: заклинания `C`, препятствия `O`, поиск стека по клетке `E`, урон `D`, раунды `R`, … |
| `BG` | — | текущее действие: тип `A`, атакующий/цель `S`/`D`, заклинание `X` … |
| `BH` | сторона 0/1 | герой в бою: номер `N`, заклинания `M`, флаг «колдовал» `C` … |
| `BF` | — | препятствия поля перед боем |
| `MR` | — | подмена сопротивления магии внутри расчёта (триггеры MR0/1/2) |
| `MF` | — | хуки способностей монстров: коэффициент защиты, блок, урон ненависти (MF0/1/2) |

Требование к порту: всё это должно действовать на **реальную симуляцию**, поэтому идёт через адаптер боя,
работающий внутри собственного боя Olden Era (см. `Compatibility/Architecture.md` §Бой).

## 3. Карта приключений

* Посещение объектов: `EventERM(герой, клетка, MixPos)` → `ERM2Object(pre)` → родное посещение →
  `ERM2Object(post)`. Триггеры `OB x/y/l`, `OB тип/подтип`, `OB тип`, `$OB…`. Скрипт может отменить родное
  посещение (`OB:S` — «выключить стандартное поведение») — порту нужен *запрет посещения до него*
  (`WoGEvent.CancelNative`).
* Ресиверы объектов (`MN SC CH WT KT FR LN ST WG SK SP WM SW MT GD ML DW WH SY GR SR SG UR PM CB`) читают и
  пишут состояние объекта (владелец, содержимое, флаги посещения). WoG хранит доп. ERM-данные объектов в
  `ERM_Object[]` (подсказка, флаги отключения) — сохраняются.
* Перемещение героя: `HM` перед каждым шагом; `HE:P` — телепорт; `PO` — ERM-данные клеток (массивы `Square`,
  `Square2`, 4 значения на клетку, сохраняются).
* Правка карты: `UN:I` поставить объект, `UN:O` убрать, `TR` ландшафт, `MO` монстры, `AR` артефакты на карте,
  `LE` локальные события, `GE`/`CE` глобальные события и события городов.
* Таймеры: `TM` (по дням), `TL` (реальное время, 3.59).
* Бродячие монстры (`MW`, `womo.cpp`): монстры, которые ходят по карте к цели.

## 4. Города (`casdem.cpp`)

* Ресивер `CA`: постройки (`B` построить/проверить/разрешить), существа жилищ (`M`), гарнизон (`G`),
  владелец (`O`), имя (`N`), тип (`T`), …; триггеры ратуши `!?TH0/1`; `CA:R` — флаг «строить ещё раз».
* Снос городов (`CD`, опция 4) и кнопка «Снести» в городе.
* Жилища 8-го уровня (опция 0, `PL_ExtDwellStd`): внешние жилища дают одно существо 8-го уровня в неделю в
  города с соответствующим жилищем 7-го уровня (S4 §8th Level Monsters).
* **[3.59]** триггеры дохода/прироста `CI`.
